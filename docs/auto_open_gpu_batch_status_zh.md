# AutoOpen 当前实现与基线

本文统一维护当前工作区中推门、拉门两种 AutoOpen 模式的有效逻辑和验收基线，不分别维护两套入口或控制框架。已完成批次的结果只代表其采集时的代码，不代表尚在验证的工作区版本。

## 代码快照

- 分支：`auto-open`
- 实现版本：当前工作区；推门已验收基线和拉门最近整批结果分别见文末。
- 主状态机：`gr00t/rl/scripts/doorman_auto_open.py`
- 领域模块：`gr00t/rl/auto_open/`
- 唯一实验入口：`gr00t/rl/scripts/run_auto_open.sh`
- 本文不以单元测试通过代替严格数据验收；数据验收失败即 episode 失败。

`doorman_auto_open.py` 明确维护顶层阶段图；几何、规划、控制、生命周期、运行时和 I/O 分别由 `geometry.py`、`planning.py`、`control.py`、`lifecycle.py`、`runtime.py` 和 `io.py` 实现。单环境和多环境运行时共用 GPU 常驻的 `TensorDoorFSM`；`DoorController` 只在初始化和稀疏规划边界提供静态任务配置，不参与逐帧 `command/advance`。

## 固定运行入口

所有 AutoOpen 运行必须通过：

```bash
DOOR_MOTION=push SEED_START=1700 SEED_END=2699 \
bash gr00t/rl/scripts/run_auto_open.sh
```

任务模式由 `DOOR_MOTION=push|pull` 选择，默认 `push`。拉门使用完全相同的脚本，只将其设为 `pull`；不另设拉门正式入口。它与采集模式 `AUTO_OPEN_MODE` 是两个独立配置：

| 采集模式 | 推门、拉门共用的行为 |
|---|---|
| `official`（默认） | 无相机完整采集、严格筛选、通过样本补双相机、严格复验及正式发布 |
| `canonical` | 仅无相机完整采集及严格验收，不启动后续图像链路 |
| `debug` | 六相机完整采集及严格验收，输出六视角拼接视频，不正式发布 |

四卡拉门无视频成功率测试的配置为：

```bash
AUTO_OPEN_MODE=canonical DOOR_MOTION=pull GPU_IDS=0,1,2,3 \
SEED_START=1700 SEED_END=2699 bash gr00t/rl/scripts/run_auto_open.sh
```

默认 `AUTO_OPEN_MODE=official`，用户只配置闭区间 `SEED_START`/`SEED_END`：先对完整 seed 区间进行无相机控制采集和严格验收，再自动提取通过 seed，通过逐帧恢复规范轨迹补采机身与腕部两路相机，最后再次严格验收并发布到 `datasets/auto_open/releases/`。图像阶段不重新运行策略、FSM 或 PhysX。各次采集是并列的独立数据集，不维护“最新版本”指针。

少量 seed 的诊断使用同一入口的 `AUTO_OPEN_MODE=debug`：六相机直接跑完整区间，然后执行同一套严格验收和通过 seed 筛选，结果写入 `datasets/auto_open/debug/`，不补图、不发布为正式 release。

无相机规范源保存在 `datasets/auto_open/canonical/`，其中保留所有通过和失败 shard 以供审计；只有补图后全部通过严格验收的数据才能进入 `releases/`。正式名称固定为：

```text
auto_open_v1_seeds<start>-<end>_episodes<accepted>_dual_camera_<YYYYMMDD>
```

固定运行参数包括：

- 推门每个 episode 默认最多 `4000` 个 50 Hz 控制步，拉门默认 `16000` 步；各阶段仍有各自预算；
- 控制、候选筛选、路径规划及逆映射共用 GPU 张量接口；逆映射去掉重力力矩补偿，不回退 CPU 逐候选求解；
- 门板间隙使用 GPU 后端；
- 各阶段轨迹在入口将所有路径点批量送入统一 GPU 逆映射，不逐帧重复调用；
- 同日重复相同区间时，只有 seed 区间和控制/采集源码指纹均一致才复用完整规范源；正式 release 已存在时校验后直接返回；
- 每张物理 GPU 恰好启动一个 Isaac Sim 进程；分配到该 GPU 的所有 seed 在同一进程中作为 vectorized env 运行；
- `SEED_START`/`SEED_END` 生成连续 seed 集合；不存在每卡 250 个槽位的上限；
- 每个 episode seed 与 GPU、rank、env 槽位、batch size 和相机模式解耦；
- `dual`/`six` 为每个 env 创建独立的 render-only Camera，逐 seed 应用确定性挂载和标定随机化；相机不注册为 physics scene sensor，不参与 reset、控制或物理推进。

同一个 seed 使用确定性的无界环境位置映射，不预留固定数量的空环境槽位。场景参数、机器人初态、任务目标、相机标定和策略输入行不依赖 GPU、rank、env 槽位或 batch size。相机模式不得改变控制或物理轨迹。

逐帧控制链使用统一的 batch-invariant 数学接口，没有阶段、seed 或接触状态特判。GPU PhysX 开启 enhanced determinism，并固定为一个 dynamics partition，但共享 GPU 物理场景在不同环境批量下的接触求解仍可能产生微小差异及闭环放大，不能保证所有 seed 跨批量逐 bit 相同。正式补图使用 canonical 中记录的状态逐帧恢复，不重新仿真，避免把重新控制运行当作同一轨迹的图像补采。

## 顶层阶段图

所有阶段处于同一层级。每个阶段拥有独立步数预算，不存在跨阶段累计计数。

| 阶段 | 主要控制 | 主要验收 | 预算步数 |
|---|---|---|---:|
| `APPROACH` | 跟踪门相对底盘站位；机械臂保持初始关节姿态 | 底盘位置、yaw 和实测速度稳定 | 1000 |
| `PREGRASP` | 保持底盘；执行预抓取 EE 路径 | 路径完成，EE/底盘稳定且无异常接触 | 500 |
| `OPEN_GRIPPER` | 保持预抓取位姿；张开夹爪 | 预抓取仍有效且夹爪开度稳定 | 100 |
| `CENTER_HANDLE` | 夹爪张开，沿规划路径插入把手通道 | 把手在 pocket/channel 内对中且 EE 稳定 | 800 |
| `GRASP_HANDLE` | 保持 EE，持续下发夹爪闭合目标 `0 rad` | 双侧、带力且稳定的对向接触成立 | 400 |
| `PRESS_HANDLE` | 保持夹持，绕把手轴按压 | 锁舌达到释放裕量 | 900 |
| `PUSH_PULL_DOOR` | 保持夹持，绕门轴前推或后拉 | 门缝达到目标、夹持保留且门速满足释放窗口 | 900 |
| `RETURN_HANDLE` | 保持夹持并沿返回路径复位把手 | 把手回到水平附近并稳定 | 150 |
| `OPEN_AND_CLEAR` | 张开夹爪并离开把手 | 夹爪张开且上下爪不会勾住把手；后挡板的分离接触不作为全接触清零要求 | 100 |
| `RETREAT_ARM` | 执行离开把手的回撤路径 | 路径完成且 EE 稳定 | 200 |
| `RESTORE_GRIPPER` | 执行随机化后的六自由度收回路径并闭合夹爪 | 实际 EE 到达同一几何目标、姿态正确且稳定 | 300 |
| `PULL_CLEAR_SWEEP`（拉门） | 入场朝向后退 0.20 m，再前往选中站位；保持收回关节角 | 最终站位稳定，机身投影通过墙面和门框避让 | 1000 |
| `PULL_INSERT`（拉门） | 闭合夹爪在门旋转半径外对准门缝，再直线伸入 | 路径完成、EE 到位稳定且夹爪闭合，不要求建立接触 | 900 |
| `PULL_OPEN`（拉门） | EE 位置绕门轴旋转，世界系方向固定，使用门速反馈 | 门角至少 30 度，并达到开门角或舒适区边界 | 900 |
| `PULL_ARM_RETRACT`（拉门） | 保持底盘，复用共享收臂接口 | 收臂完成且实际机械臂稳定 | 300 |
| `PULL_BASE_ADVANCE`（拉门） | 预计算靠墙前肩沿墙的 arcsin 朝向轨迹，按发布点夹角与门角比较决定是否推进 | 参考点暂停且底盘到位稳定、门速低；门角足够则直接 THROUGH | 1000 |
| `ALIGN_PANEL`（推门） | 保持机械臂关节角；底盘跟踪门板站位 | 底盘在门板站位稳定 | 400 |
| `CONTACT_PANEL` | 保持底盘；EE 渐进到门外 standoff | 实际 EE 达到门板相对目标并稳定 | 400 |
| `PUSH_OPEN` | 保持底盘；受速度和力约束地推门 | 门角足够，或机械臂超出舒适区需要换位 | 900 |
| `PUSH_ARM_RETRACT` | 保持底盘；收回机械臂 | 实际 EE 到达本次随机目标且姿态、速度稳定 | 300 |
| `BASE_ADVANCE` | 机械臂保持；底盘前往单调前进的安全再接触站位 | 接触点重新进入机械臂范围且底盘稳定 | 900 |
| `THROUGH` | 跟踪门框相对的尾部净空目标，同时恢复机械臂 | 尾部越过门框 1 m，底盘/机械臂/夹爪/门均稳定 | 1100 |
| `SUCCESS` | 保持最终命令 | 终态 | 无 |
| `FAILURE` | 保持失败命令 | 终态 | 无 |

共享前半段为：

```text
APPROACH
-> PREGRASP -> OPEN_GRIPPER -> CENTER_HANDLE -> GRASP_HANDLE
-> PRESS_HANDLE -> PUSH_PULL_DOOR -> RETURN_HANDLE
-> OPEN_AND_CLEAR -> RETREAT_ARM -> RESTORE_GRIPPER
```

三个物理旋转依次是绕把手轴、绕门轴、绕把手轴；第二段根据推门/拉门选择前推或后拉。推门后半段为 `ALIGN_PANEL -> CONTACT_PANEL -> PUSH_OPEN -> THROUGH -> SUCCESS`。

机械臂超出舒适区时，推门路径插入：

```text
PUSH_OPEN -> PUSH_ARM_RETRACT -> BASE_ADVANCE -> CONTACT_PANEL
```

该循环可以执行多次；每次进入 `PUSH_ARM_RETRACT` 都重新采样收回目标。

拉门后半段为：

```text
RESTORE_GRIPPER -> PULL_CLEAR_SWEEP -> PULL_INSERT -> PULL_OPEN
-> PULL_ARM_RETRACT -> PULL_BASE_ADVANCE -> CONTACT_PANEL -> PUSH_OPEN
```

首次拨门完成后不再重复拨门，后续复用 `CONTACT_PANEL/PUSH_OPEN` 推板；门角不足则循环 `PULL_ARM_RETRACT -> PULL_BASE_ADVANCE -> CONTACT_PANEL -> PUSH_OPEN`，不进入推门专属的 `BASE_ADVANCE`。门角达到 89 度后，若机械臂仍伸出则先收臂，之后直接 `THROUGH`；若已在底盘移动则直接交接。已删除独立对准门框阶段及其 `gap_distance_m` 参数，不再先前往门框前方 0.77 m 的站位，也不直接将开门角达标视为任务成功。

### 拉门站位与选点

- 首次站位以门框自由侧为局部参考，在 `x=0.375-0.425 m`、`y=0.725-0.900 m`、`yaw=-105 至 -95 度` 的区域联合采样 32 个候选，再按门的镜像方向映射到世界系。选择墙面/门框净空及完整伸入路径逆映射均合格的候选；最多四轮选站是后备机制。
- 首次横移将入场位姿、沿入场 yaw 后退 0.20 m 的位姿、选中站位预计算成同一条连续轨迹，逐帧取点。中间路段不等待实际到位或静止窗口；轨迹播完后持续发布终点，最终避让及实际稳定验收保持不变。
- 第一次伸入使用 9 个高度（世界系 0.80-1.20 m、步长 5 cm）和 3 个插入长度（2/4/6 cm），共 27 个候选，避开把手硬件高度。先在旋转半径外对准门缝中心，尖端保留 3 cm 径向间隙，再沿固定轴向直线前伸；不增加朝向随机化，不要求接触成立。
- 首次拨门保持世界系夹爪方向不变，位置绕门轴旋转，门速反馈和 2 度超前量上限复用推门接口；至少达到 30 度后才允许按舒适区边界结束。
- 后续贴门板移动在阶段入口选择靠墙的前肩 A，固定其墙法向坐标，沿墙向门轴 B 的投影方向预计算轨迹，直到 A 与 B 具有相同的墙面切向坐标。令 a=|AB|、alpha 为 AB 与墙的夹角、b 为机身碰撞体宽度加 10 cm，则每个几何点 beta=clip(arcsin(b/a)+alpha, 入场机身与墙夹角, 90 度)；a<b 时按 90 度处理。用 beta 及肩部相对机身偏移反算底盘位置和 yaw，轨迹生成函数不接收门角。入场朝向与首个几何点不同时，绕固定肩部按限速衔接首点。整段一次性在 GPU 预计算，不逐 env、逐点调用 CPU。
- 贴门板轨迹发布时，只有当前发布点 beta 小于真实门角才推进一帧；否则保持当前参考位姿、参考速度置零。门角回落不使索引后退；门角继续增大可恢复推进。这个门角发布门控是任务明确要求，不是按实际跟踪误差暂停轨迹。底盘继续通过原速度控制器追踪当前发布点，门控暂停后仍要求实际到位及包含低门速的 25 帧零指令稳定窗口，才进入 CONTACT_PANEL。不要求预计算轨迹全部播放完，也不继续使用“朝向始终平行门板”的单点反算。
- 后续推板沿用共享接触规划。搜索基准是当前 trunk 前端后退 10 cm 在门板上的投影；沿板方向正负 0.40 m、步长 0.05 m，与 9 个高度组合为 153 个候选。闭合夹爪终点距门板 3 cm，并避开把手高度；完整路径的接触安全不能仅由终点间隙推断。

## 底盘控制

底盘移动阶段使用目标状态牵引，不直接长期发布固定速度。保持站位阶段在进入时锁存前一移动阶段的目标，而不是锁存带瞬时跟踪误差的当前位置。

共享 `approach_distance=0.85 m`：底盘根部沿门法向距把手抓取中心 0.85 m，朝向门板。该值也用于派生推门 `ALIGN_PANEL` 站位及后续参考线；不是夹爪净空。APPROACH 保持 episode 初始机械臂关节角。统一到位配置为位置内/外阈值 2/10 cm、yaw 内/外阈值 0.05/0.15 rad，静止窗口 25 帧；各阶段附加验收仍独立。2026-10-23 按用户要求由 0.82 m 调整为 0.85 m；下文历史批次仍保留运行时数值。

全局约束：

- 平面速度上限：`0.4 m/s`；
- yaw 角速度上限：`0.6 rad/s`；
- 控制器决定继续移动时，任何非零平移指令的模长至少为 `0.15 m/s`，不再另设距离启用阈值；
- 控制器决定继续转动时，任何非零 yaw 指令的绝对值至少为 `0.2 rad/s`，不再另设角度启用阈值；
- 反向命令需要连续确认，并经过零速锁定，避免短时正负翻转；
- `APPROACH` 和 `ALIGN_PANEL` 共用同一个到位状态机和阶段配置；
- 首次进入阶段配置的内阈值后发布严格零速度，并开始累计静止窗口；
- 静止期间允许漂移至外阈值以内；超过任一外阈值立即取消窗口并恢复目标追踪；
- `BASE_ADVANCE` 的再接触/肩部安全和 `THROUGH` 的整机三维稳定/直立/门速要求是阶段附加条件，不改变统一到位语义。

`BASE_ADVANCE` 每步根据当前门板几何更新目标站位：目标尽可能前移，使门板接触点进入 `0.4 m` 再接触半径，同时满足前肩安全约束；再接触释放阈值为 `0.45 m`，目标带 `0.05 m` 提前量。目标纵向位置只能前进，不能后退；横向基准固定在门框中心。

`THROUGH` 的目标不是累计前进距离，而是机器狗尾部越过门框平面 `1.0 m` 的门框相对状态。终态同时要求实际速度稳定。

### 底盘预计算轨迹模式

`base_trajectory.py` 提供推门、拉门共用的 GPU 批量平面位姿轨迹接口。阶段入口按位置和 yaw 路点预计算连续样本，参考轨迹默认线速度不超过 0.25 m/s、角速度不超过 0.40 rad/s，yaw 使用最短角差；每个 50 Hz 控制周期推进一个样本，结束后持续发布终点。没有按实际跟踪误差暂停推进、路段交界等待实际对准、或根据实际状态重规划的逻辑。实际状态仅参与闭环速度跟踪和阶段验收。

参考位姿及参考速度通过共享底盘目标跟踪器转换成机身系 `vx/vy/wz`，再发给原 whole-body controller；实际速度指令仍保留原有上限、最低非零速度及反向指令处理。参考轨迹的限速不等于新增低层接口或改变验收标准。

- `PULL_CLEAR_SWEEP` 使用同一条轨迹完成先退 20 cm、再横移到站位，不再逐路点等待到位窗口。
- `THROUGH` 在同一阶段内部预计算门框外对齐位置/朝向、随后前进穿门的轨迹；若入场位置不足以容纳转向，先沿门法向移至依据当前机器人碰撞包络计算的外侧平面。不恢复独立 `PULL_ALIGN_FRAME` 阶段，也不恢复固定 0.77 m 参数。轨迹规划不等于已证明整条真实运动无碰撞。
- 位置保持等阶段仍可使用原目标跟踪接口；贴门板移动复用同一个轨迹缓冲区，仅增加上述明确的门角发布门控。

轨迹接口、贴墙 arcsin 曲线及接入修改的定向测试为 114 passed、2 skipped（3 项此前未通过的拨门/伸入测试未纳入本组）；随后补充了 THROUGH 轨迹进度计数器类型的 CPU/CUDA 专项回归。连续轨迹版本现已完成下文 `20261023T141632` 的 1000-seed 严格验收，结果不代表全部碰撞问题已经解决。

## 机械臂控制

### 控制模式

- `APPROACH`、`ALIGN_PANEL`、`BASE_ADVANCE` 等保持机械臂的阶段使用关节控制；
- EE 运动阶段使用 Cartesian 目标或预计算的稠密路径；
- EE 控制阶段保留位置和姿态限速，不再叠加会改变 Cartesian 轨迹的逐关节限速；
- 关节模式由低层统一限速；
- Cartesian/关节模式切换从当前实际关节状态连续进入，避免单帧目标跳变；
- 机械臂实际 actuator stiffness 与稳态模型共用同一配置。

### 预抓取与抓取

PREGRASP 在阶段入口批量尝试 `0/5/10/15/20 deg` 俯仰候选，保持固定爪相对把手的垂直预留量，选择首个精确可达解。路径只计算一次，执行期间不逐帧重算 IK。

CENTER_HANDLE 的语义是：

- 门板法向和把手轴向：把手中心对齐 `pocket_capture_center`；
- 竖直方向：把手中心对齐上下夹爪通道的 `channel_center`；
- 对中误差阈值：法向/轴向 `5 mm`，竖直 `10 mm`；
- 夹爪在把手轴向上必须保留端部余量：轴座侧至少 `20 mm`，自由端至少 `10 mm`。

GRASP_HANDLE 始终向上层记录闭合命令 `0 rad`。接触后是否停止继续加力属于夹爪低层闭环，反馈开度只记录为 observation，不能反写成监督命令。垂直平衡修正最大范围为 `30 mm`。

### 门板接触与推门

推门名义基准点使用门铰链侧底部为原点的固定偏移：沿门板切向 `0.4 m`、高度 `1.0 m`，不使用门板几何中心；拉门推板的名义切向基准由当前机身站位投影确定。

每次进入 CONTACT_PANEL 时：

1. 推门和拉门共用门板与当前机械臂平面工作空间的区域候选：10个径向位置、9个高度、7个yaw，共630个；保留板边、距轴至少20 cm及把手高度避让；
2. GPU批量检查静态可达、精确inverse、关节裕量及后续推弧；
3. 拉门保留至少5度有效推进要求及原选择次序；推门按可用推弧最长优先，不再用单次至少5度拒绝所有短弧，舒适边界处沿用已有收臂/前进换站；
4. 夹爪指定尖端保持在门板外 `30 mm`；
5. 位置和姿态均从当前命令连续渐进，位置每周期最大变化 `3 mm`。

PUSH_OPEN 以 `20 deg/s` 为门铰链目标角速度，夹爪尖端参考角动态提前量上限为 `4 deg`，EE 位置目标每帧最多移动 `3 mm`。门板接触点超过机械臂舒适范围后，先收回机械臂，再让底盘前进，之后重新计算 CONTACT_PANEL 目标。

### 收回目标随机化

RESTORE_GRIPPER 与 PUSH_ARM_RETRACT 共用中心目标，坐标为 B2Z1 goal-reference-local 的：

```text
[x, y, z, roll, pitch, yaw] = [0.30, 0.0, 0.30, -pi/2, 0.0, 0.0]
```

每次进入任一状态时独立采样：

- 位置：半径 `0.05 m` 球体内按体积均匀采样；
- 姿态：roll、pitch、yaw 分别在 `+-5 deg` 内均匀采样；
- 同一 episode 内不同入口不复用样本；
- 每批生成 `64` 个候选并一次执行 GPU batched IK；
- 精确可达标准：位置误差 `<=1e-4 m`、姿态误差 `<=2e-4 rad`、关节限位裕量 `>=2e-3 rad`；
- 选择采样顺序中的首个精确可达候选；整批无解则继续采样，最多检查 `4096` 个；
- 无解候选绝不下发，全部写入 episode metadata；
- 验收使用本次采样后的实际几何目标，不使用中心值或命令插值变量。

## 随机化

场景、门、机器人初态和收回目标始终按 episode seed 确定性采样。机器人初始采样语义对应前端鱼眼相机的 x/y/yaw，再换算到底盘初态。

`dual`/`six` 模式按 seed、按相机独立采样安装和标定误差：位置半径 `2 cm`、旋转最大 `15 deg`、fx/fy 共同尺度 `+-8%`、principal point 半径 `5 px`、fisheye k1-k4 相对 `+-10%`。Isaac Sim 不支持的 skew 固定记录为实际值 `0`。相机随机化只改变观测，不得改变控制或物理轨迹。

## 数据采集

采集器是被动观察者，不参与 AutoOpen 决策。数据阶段唯一由逐帧 FSM 状态映射：`APPROACH` 为 `approach`，`PREGRASP` 至 `RESTORE_GRIPPER` 为 `handle_press`，`ALIGN_PANEL` 至 `THROUGH` 为 `traversal`；末尾连续 50 帧实际稳定状态为 `terminal_hold`。

控制频率 `50 Hz`，物理频率 `200 Hz`。每个 shard 包含 58 维 observation、25 维 action、完整状态审计、PhysX substep 接触、门资产路径/hash、PhysX/碰撞参数、该 seed 的实际相机标定、机器可读验收报告和中文摘要；正式发布包含双相机，debug 数据包含六相机。

状态与实采语义一致：B2 线/角速度使用 trunk 坐标系；EE 只使用机械链已有的 `0.100 m` 工具点，不重复偏移；数据集工具姿态去除 URDF gripper-link 固定网格旋转。Cartesian 控制记为 `inactive=0, reset=0`，保持当前关节角为 `inactive=1, reset=0`，运动回 middle preset 为 `inactive=0, reset=1`，到达后恢复 inactive。

终止段底盘命令必须连续 50 帧严格为零，且实际底盘、机械臂、夹爪和门速度均满足稳定阈值。接触按脚-地面、夹爪-把手、夹爪-门板、门内部和异常环境接触分类；异常接触或分类穿透超限直接隔离。数据验收不通过即该 episode 不成功，不维护第二套“控制成功率”。

## GPU 张量运行时

AutoOpen 只有 `TensorDoorFSM` 一套运行时。阶段、计时、稳定窗口、控制状态和锁存量为 GPU 张量，每帧按 stage mask 批量生成命令并验收；不逐 env 调用 `DoorController.command()/advance()`。稀疏的精确 IK 和路径规划只在阶段边界批量请求。单环境和多环境、无相机和带相机均使用同一 FSM 和同一采集器。

控制、低层策略和 PhysX 物理保持在 GPU。严格数据采集不是纯 GPU 流程：GPU PhysX contact view 在每个 200 Hz 物理子步保存接触张量，控制周期末在 CPU 聚合真实接触并写 Parquet/JSON。当前实现采用以下固定性能约束：

- 整个 USD 场景只遍历一次，统一建立所有环境的 sensor/filter 索引；
- 接触池容量按环境数配置为每环境 `256` 条，而不是按每个 sensor 重复分配；运行时记录峰值，容量触顶立即失败，不允许静默截断；
- 每个物理子步只克隆 GPU tensor，不执行逐接触 `.item()`/`.tolist()` 同步；每个 50 Hz 控制周期结束后统一搬运并聚合；
- 250 个环境的目标 FK 和 joint-mode 每帧只批量计算/读取一次，不逐环境重复执行 float64 FK 或搬运整批 mask；
- dataset manifest 只引用各 shard 的验收报告，不嵌套复制完整报告。

当前已验证：

- 一次固定入口调用可将 4 个 seed 分配到 2 张 GPU；每卡只有一个 Isaac Sim 进程、进程内 2 个 vector env，最终聚合得到 4 个不重不漏的 shard；
- 单进程 2 env 无相机采集能够独立写出两个严格 shard；
- seed 1717 在 batch=1/env0、batch=2/env0、batch=2/env1 及 GPU0/GPU2/GPU3 上均为完整 `2426` 帧；raw audit 的 `45/45` 字段逐 bit 相同；
- 当前单环境结果与修改前 partition1 单环境基线同为 `2426` 帧，raw audit 的 `45/45` 字段逐 bit 相同，证明确定性修复没有改变原单环境行为；
- `none`、`dual`、`six` 的 seed 1717 均为完整 `2426` 帧，raw audit 的 `45/45` 字段逐 bit 相同，证明相机开关不改变控制和物理行为；
- 2 env 双相机的四路图像均非黑屏，两个 env 的相机世界位姿分别对应各自场景，像素哈希不同；
- 当前单 env 双相机两路、六相机六路视频均为 `2426` 帧；首帧均非黑屏，模式内像素哈希分别 `2/2`、`6/6` 唯一。

### 本轮失败机制离线追查

本节仅读取本轮 summary、raw_audit 和 raw_contacts，未启动仿真或修改控制逻辑。统计阶段终止原因时与异常接触样本存在重叠。

1. **首次拨门存在轨迹截断与 30 度退出要求的冲突。** `begin_pull_open()` 将超出 0.7 m 舒适区的轨迹截短；若入口已经在舒适区之外，`first_outside=0`，路径长度被 `clamp_min(2)` 限为两个点。`advance_pull_open()` 却要求 `minimum_open`（至少 30 度）与开门完成/需要换位同时成立，才允许收臂。222 条无进展失败中，115 条整个阶段的实际水平 reach 最小值已大于 0.7 m；这 115 条 EE 输入目标整段位移仅 6.708-9.879 mm，最后 200 帧目标变化最多 0.0432 mm，门角峰值 7.91-18.72 度。它们不是大幅运动目标追踪失败，而是轨迹在很早的位置停止、又不能进入换位。不能直接放宽 30 度验收：应使此前选站/伸入与至少 30 度的有效拨门行程自洽；具体修复未实施。

2. **222 条无进展并不是持续顶着重门。** 对全部 222 条逐帧检查，末尾 200 帧均没有 `link06`/`gripperMover` 与 `door_panel` 的非零力接触，其中 144 条整个 PULL_OPEN 都没有这类接触；220 条末尾 200 帧 EE 输入目标变化小于 0.1 mm。每条样本的末段 EE 实际位置与记录的 inverse 输出位置之间误差中位数为 1.109-2.402 mm（跨样本中位数 2.003 mm），输入/输出位置差的末段中位数为 0.0165-0.0513 mm。不能将其笼统解释为厘米级逆映射误差或门阻力大。上述 115 条之外的 107 条，还需要区分舒适区截断、不可达点截断、有限超前量内未能接触等机制；目前的汇总没有记录每条路径的实际截断原因，不能据末段静止直接断言全部同因，也不应擅自增加接触闭环。

### PREGRASP 三段避让轨迹

原 PREGRASP 已使用轨迹缓存，但路径是当前位置到目标的直线插值。现改为阶段入口预计算三段路线，推门和拉门共用：

1. 用阶段入口实际闭爪碰撞体与实际把手胶囊计算高度区间。夹爪区间中心高于或等于把手中心则向上避让，否则向下避让；移动至区间分离并保留 2 mm 间隔，已足够分离时不增加竖直位移。
2. 保持该高度，沿朝机器人一侧的门板法向后撤，使夹爪最靠门的碰撞体边界在把手机器人侧外表面之外至少 2 cm。已达到间隔时不额外后撤，也不向门侧前进。
3. 从后撤点到既有 PREGRASP 目标位姿，保留原目标与 pitch 选择。前两段保持入口夹爪世界姿态，仅第三段插值至目标姿态。

复用既有 GPU 多路点采样器与轨迹缓存：最大平移采样间隔 2 mm、角度采样间隔 0.025 rad；整段路线仅在阶段入口统一批量逆映射，逐帧取缓存点，不增加实际跟踪误差暂停或路段停稳条件。路径超过缓存容量会拒绝规划，不截断执行；逆映射沿用 pitch 检查的 1e-4 m 位置及 1e-4 旋转误差向量范数标准检查全部保留路径点，不合格路径记录误差并拒绝执行。底盘控制、到位验收及阶段预算未改。

metadata 的 `acceptance_diagnostics.pregrasp_avoidance_inverse` 保存四个路点、姿态、实际高度区间、竖直/后撤距离和预设间隔；`arm_align_path_precision_inverse` 保存整段最大逆映射残差及是否通过。相关路径、规划器和 GPU 接口回归 `70 passed`，包括 CPU/CUDA、上下方向、左右门、路径连续性、终点不变及单 seed 批量一致性。未启动仿真，尚未验证本轮碰撞率变化。

#### 主要退化：首次对准门缝时撞门框，而非直线伸入时撞门板

PULL_INSERT 异常接触由上轮 **57/936 个进入插入规划的样本（6.1%）** 增至本轮 **612/949（64.5%）**，远非只因更多样本进入该阶段。逐帧定位全部 612 条的第一次异常接触：

- 首次碰撞发生在阶段第 17–97 帧，中位第 35 帧；首次记录力中位 181.0 N、最大 538.1 N。
- 全部 612 条此时发布的位置仍是半径外对准点，距该点仅 0.00014–0.05465 mm，尚未沿采样直线推进。实际 EE 距对准点中位 48.34 mm，最大 295.24 mm。这里没有把“碰撞发生在 PULL_INSERT”误读成“已经开始直线伸入”。

因此，0.60 m 终点限制和新站位区域实现了终点要求，却把“名义插入可达”当作了整体运动安全；前述离线 1024/1024 可行并不是碰撞自由证明。此前“半径外这一段不涉及碰撞”的前提对门框不成立，本轮据实揭示了这一点，而不是 inverse 本身求解不准。

**1. 推门板无进展的主体是轨迹遇到关节限位，不是门阻力或底盘先漂移。**

91 条 PUSH_OPEN 无进展样本全部在末段出现第 1 关节目标距硬限位约 0.001 rad。首次触限发生于阶段第 0–19 帧，中位第 11 帧（0.22 s）；此前底盘平移中位仅 0.815 mm、最大 8.13 mm，不能把大幅底盘漂移当作这一现象的先因。

**3. 抓把手 42 条以夹持接触几何失配为主，不是速度阈值，也不是大幅 inverse 位置误差。**

原始表中的两刚体均有接触不等于形成两指定爪面的有效夹持。对每条末 100 帧中各刚体的最大力代表接触点，按实际关节 FK 变换并与碰撞子形状计算最近三角面：固定侧 39 条最近于指定固定爪面、3 条为其他部位；移动侧仅 12 条最近于 `moving_convex_000` 指定爪面，27 条为其他部位，3 条几何距离不足以明确区分。此为代表点分类，不冒充全部接触流的精确接触子形状标签。它支持主体是把手接触落点/包络不匹配，而非“爪根本没碰到把手”或瞬时速度误判；不能将剩余各子组全归为同一几何偏差。

同时发现 `_opposed_grasp()` 仍包含接触点沿把手轴向距端部至少 5 mm 的约束，与此前要求删除该条件不一致。其对这 42 条的独立贡献尚未从规范化传感器接触点逐帧复原，不能把全部失败归因于此；本次未修改该条件。

#### 本轮退化主因：新选点与未变的速度/接触控制不匹配

132条超速是最主要新增损失，不是GPU逆映射算不准导致的同一类静态不可达。12条按目录顺序抽取的超速记录中，11条选中 `(-30 cm,+5 cm,+30°)`，1条选中 `(-25 cm,0,+10°)`。采样记录的板面切向距门轴从原0.496–0.739 m降到0.196–0.439 m；门板峰值力190.01–533.97 N，失败时门速0.5259–0.5519 rad/s，越过原30°/s阈值。

可以确认的代码/日志因素：

- 速度PI仍以20°/s为目标，EE位置仍限制每帧3 mm。点更靠近门轴之后，原3 mm/帧对应的角速度上界提高，不能假设原先接触点上的速度响应保持不变；没有改反馈增益或速度门限。
- PUSH_OPEN仍保持接受时的世界系夹爪姿态，EE中心则按门轴旋转。允许偏转后，固定夹爪包络沿旋转门法向的支撑投影会改变；11条+30°样本在超速前额外向门板侧变化1.57–6.71 mm。目标包络的最小法向间隙为 -23.11 至 -31.69 mm，含既有预压和角度提前量，不应误称为真实刚体穿透深度。
- 离线按原PI公式复算，超速末3帧的反馈提前量已为负，约-0.82°至-2°，不是“超速后反馈还一直增加提前量”。已施加的接触力、几何侵入需求及门的运动不会因此瞬间消失；当前速度/接触控制未能在这组新点位下避免连续3帧超限。

以上是同时存在、由数学几何与日志确认的因素，尚未做分离变量的物理实验，不虚报各因素独立贡献比例。按照用户“新的问题只分析”的边界，未修改PI、3 mm限速、门速度验收、门动力学或接触材料，也未因这些新问题继续擅自调参。
