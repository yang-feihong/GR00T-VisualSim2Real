### 主动目标误差设计

#### 设计纠正：随机化必须按任务语义拆分

下面已经完成的统一 `target_noise_scale` 实验只能说明一组绑定比例会如何改变闭环结果，不能
回答底盘、抓取和推门各自允许多大随机性。它把底盘与 EE 幅度绑定，并把 EE 三个平移轴、
三个旋转轴视作等价自由度；这个设计不符合开门任务的物理结构。`scale=0.1` 因而不再作为
数据采集建议，只保留为错误实验设计的对照记录。新的正式实现和实验必须按下表拆分。

坐标约定：`n` 为门板朝机器人侧的法向，`h` 为把手轴向，`z` 为世界竖直方向。夹爪闭合
方向位于 `n-z` 截面内；门关闭时通常接近 `z`，但有俯仰候选时不能简单等同于世界竖直轴。

| 动作链 | 语义自由度 | 是否随机化 | 初始候选范围 | 物理依据与约束 |
|---|---|---|---:|---|
| `APPROACH` 站位 | 沿门法向 `n` | 是，独立变量 | `±0.10 m` | 人可以在前后约 10 cm 的不同站位完成伸手抓门；仍以名义站位验收，实验测量控制误差叠加后的真实保留率 |
| `APPROACH` 站位 | 沿门切向 | 是，独立变量 | `±0.10 m` | 人可以偏左/右站立后由机械臂补偿，但受机械臂工作空间和门框通行约束 |
| `APPROACH` 站位 | yaw | 是，独立变量 | `±0.10 rad` | 小角度斜站仍可操作；与位置误差分开标定，不能用一个 scale 绑定 |
| `PREGRASP→CENTER_HANDLE→GRASP_HANDLE` | 沿把手轴向 `h` | 是，共享一个 episode 偏差 | `±0.02 m` | 握在把手轴线不同位置仍是有效抓取；三个阶段必须共享，避免先对准一个点、直线前伸时又换点 |
| 同一抓取链 | 夹爪闭合方向 | 是，但仅毫米级 | 从 `±0.002 m` 扫描 | 决定把手是否位于上下夹爪之间；偏差过大会直接失去双侧夹持 |
| 同一抓取链 | 门法向插入深度 `n` | 是，但仅毫米级 | 从 `±0.002 m` 扫描 | 太浅不能形成稳定包络，太深会碰门板；与把手轴向的厘米级冗余不是同一性质 |
| 同一抓取链 | 绕把手轴的 roll | 条件可随机 | 从 `±0.01 rad` 扫描 | 会改变上下包络余量，应独立于位置标定 |
| 同一抓取链 | 使夹爪轴偏离门法向的两项姿态 | 原则上不作为自由随机误差 | 默认 0 | 它们会破坏直线插入和双侧夹持；只有作为可达性规划的离散俯仰候选才有明确语义 |
| `TURN_HANDLE` | 任意笛卡尔终点偏移 | 禁止 | `0` | 夹住后轨迹必须围绕真实把手转轴；当前统一实现额外扰动终点会主动拉离把手，应删除 |
| `TURN_HANDLE` | 下压角与开门缝余量 | 条件可随机 | 后续按锁舌阈值单独标定 | 可以改变动作幅度，但必须始终高于开锁/门缝验收阈值，整条圆弧由一次采样参数生成 |
| `CONTACT_PANEL→PUSH_OPEN` | 门板面内水平接触点 | 是 | 从 `±0.10 m` 扫描 | 推门不要求固定命中门板中心；候选必须位于门板边界安全余量内且 IK 可达 |
| 同一推门链 | 门板面内高度 | 是 | 从 `±0.10 m` 扫描 | 人可以推门板不同高度；同样受边界和 IK 可达性约束 |
| 同一推门链 | 门法向悬停/预压深度 | 是，但仅毫米级 | 从 `±0.002 m` 扫描 | 直接决定接触速度、穿透和接触力，不能与面内接触点共用厘米级幅度 |
| 同一推门链 | 夹爪轴与门法向夹角 | 是，但小角度 | 从 `±0.01 rad` 扫描 | 偏角会形成边缘接触和切向力；必须独立标定 |
| 释放、后撤、恢复 | 安全撤离终点 | 条件可随机 | 按安全间隙分别定义 | 可以扩大无接触撤离数据，但不能给三个终点各采独立噪声造成折线路径 |
| `THROUGH` | 尾部越门距离、门洞横向、yaw | 是，三项独立 | `±0.10 m/±0.08 m/±0.08 rad` | 穿门终态存在站位冗余，但尾部安全距离不能采到门框前侧 |
| `THROUGH` | middle preset 各关节 | 暂不做逐关节独立白噪声 | `0` | 任意关节噪声不对应人的任务意图；若需要机械臂姿态多样性，应定义经碰撞与限位验证的整组收回姿态 |

候选范围是第一轮单变量边界搜索的上限，不是已经验证可用的最终分布。每个变量先单独扫描；
只有单变量结果通过后才进入组合实验。名义验收不跟随采样目标平移，避免把“命令产生变化”
误报为“任务仍然成功”。若物理上合理的把手轴向 `±20 mm` 被当前 `5 mm` 几何验收拒绝，
必须单独报告为“验收定义与任务冗余冲突”，不能暗中移动验收目标或把失败归因于控制器。

新接口使用可重复的 `--target_noise NAME=MAX_ABS`，每个未指定变量严格为 0。当前已删除统一
比例接口、TURN_HANDLE 任意笛卡尔终点偏移和 THROUGH 各关节独立白噪声。抓取链的
PREGRASP/CENTER_HANDLE 复用同一 `grasp_chain` 样本；CONTACT_PANEL 在面板网格 IK 搜索前
采样接触点与姿态，随后围绕该点一次性完成批量可达性搜索，PUSH_OPEN 继承同一接触锚点。
TURN_HANDLE 只支持非负的下压余量与门缝余量，整条轨迹仍严格绕真实把手转轴生成。

4-env 非零接口冒烟使用了 `approach_normal_m=0.02`、`grasp_handle_axis_m=0.01`、
`grasp_closing_m=0.001` 等组合，仅用于检查接口而非估计成功率。四个 seed 的实际把手轴向
样本依次为 `+8.05 mm、+6.03 mm、-9.24 mm、-0.07 mm`；前三个全部超时于
`CENTER_HANDLE`，只有接近零的第四个继续成功。这与当前
`|pocket_axial_error|<=5 mm` 验收直接一致，说明它首先暴露的是“物理允许沿把手换握点，但
验收仍要求回到把手中心”的定义冲突，不能据此声称机械臂只能承受亚毫米随机化。该冲突在
后续轴向单变量实验中单独统计，暂不擅自修改验收标准。

#### 旧统一比例实验（已废弃，仅保留历史数据）

旧实现采用独立于场景 RNG 的 episode RNG，以 `episode seed` 派生。每个语义目标第一次使用时
采样一次并按标签缓存；滚动重规划、每帧反馈和同一轨迹后续访问均复用同一偏差。metadata 会
记录实际采样值。旧 `--target_noise_scale=0` 默认值会直接返回原值且不消耗随机数；该参数现已
从代码删除。

scale 1 的各维均匀分布上限暂定为：底盘门坐标系位置每轴 `±20 mm`、yaw `±0.02 rad`；
EE 门坐标系位置每轴 `±2 mm`、姿态旋转向量每轴 `±0.01 rad`；THROUGH middle preset
各关节 `±0.01 rad`。后续实验使用统一 scale 从小到大缩放这些上限，而不是边试边修改各项
定义。

| 类别 | 扰动位置 | 验收参照 |
|---|---|---|
| 底盘任务目标 | APPROACH、ALIGN_PANEL、THROUGH 的目标位姿 | 原始名义目标 |
| 机械臂路径 | PREGRASP、CENTER_HANDLE、TURN_HANDLE、释放/后撤/恢复的路径终点在生成整段路径前扰动 | 原始几何目标或物理事件 |
| 门板操作 | CONTACT_PANEL 的可达点选定后、稳态逆映射与 PUSH_OPEN 轨迹生成前扰动一次 | 原始门板站位与接触几何 |
| 关节目标 | THROUGH 的 middle preset | 原始 middle preset |
| 不扰动 | 进入阶段时锁存的当前关节角、BASE_ADVANCE 肩部安全目标 | 保持与安全语义不变 |

当前纯数学与既有几何测试为 `8 passed`。额外审计已确保 `scale=0` 不改变数组值或 dtype，
对应目标噪声单测为 `3 passed`。首轮配对扫描已完成，输出目录为
`logs_rl/auto_open_target_noise_sweep_20261011`：四张卡分别运行 `scale=0/0.5/1/2`，

### “向前力”是法向力，不是摩擦力

`step=840` 移动爪给把手的法向反作用为：

```text
F_normal,moving = [-96.470, -54.118, +87.506] N  (world)
```

其中 `-96.470 N` 就是朝门的前向分量。摩擦反作用为
`[+34.794, +0.584, +33.453] N`，其 X 分量反而抵消了 36.1% 的前向法向力；
移动爪法向加摩擦后仍有 `-61.676 N` 前向分量。因此不能把前向力解释为摩擦拖拽。

同一时刻固定爪给把手的法向反作用为
`[+31.705, +26.909, -44.307] N`。两爪法向合力为
`[-64.765, -27.209, +43.198] N`；把两爪摩擦也计入后，瞬时总 X 力约为
`-4.05 N`。所以 141 N 是“移动爪法向合力模长”，不是把手所受总前向力。真正失去平衡
发生在三帧后的单侧接触阶段。

### 凹槽为什么没有把把手稳定收回

在 `step=840`，PhysX 法向与“接触点指向把手圆柱轴线”的方向余弦为 `0.99996`，法向
本身没有算反。此时把手中心相对代码定义的 pocket center 在夹爪局部 X/Z 平面上的误差为
`[-6.90, +3.22] mm`；移动爪反作用在 EE 局部系为
`[+74.59, +4.25, -118.78] N`。因此这一帧的力同时具有两个性质：

1. `+X` 在世界系表现为向门前推；
2. 对当时位于 pocket 后上方的把手而言，`+X/-Z` 也确实含有回中分量。

二者并不矛盾。凹槽回中不是“始终产生一个独立的反向 X 力”，而是由接触面法向指向当前
截面中心；当把手位于 pocket 后方时，回中力本来就包含朝门的 `+X` 分量。

没有稳定回中的根因是双爪没有在同一把手截面形成对称约束。`step=840` 固定爪主接触位于
把手轴向 `+21.16 mm`，移动爪主接触位于 `-56.99 mm`，两点沿把手轴相隔 `78.14 mm`。
门开始打开后，夹爪横向轴与实测把手轴的误差从约 `0.13 deg` 增至 `2.31 deg`，随后在
接触失稳过程中达到 `5 deg` 以上。两个爪因此压在把手轴向两端的对角边缘，而不是在同一
截面的上下凹面形成稳定夹持。

这项轴线误差来自 TURN_HANDLE 门缝段的姿态目标使用路径内的计划门角，而不是每帧把夹爪
横向轴严格锁到实测门板/把手轴。10 度预抓取俯仰本身不是固定在世界系：代码先绕把手轴
施加该俯仰，TURN_HANDLE 再用同一把手轴左乘旋转整套抓取姿态；因此“始终保留世界系
pitch=10 deg”不是本次根因。

## 当前 AutoOpen 各阶段控制与验收

下表记录的是正式工作区当前反馈控制 FSM 的实际代码行为，不是期望设计。`RESET`、`SUCCESS`
和 `FAILURE` 是初始化或终止状态，其余 17 个阶段按执行顺序排列。机械臂一栏中的“验收”也列出
了决定阶段切换的门、把手和接触条件；没有条件时明确写为“无独立验收”。

每次进入新阶段都会把 `stage_steps` 清零，因此该字段始终表示当前阶段的局部步数。不存在跨
阶段累计计数或共享超时预算；每个阶段只根据自己的 `stage_steps` 和独立上限判断超时。
新增展平阶段的预算分别为：`OPEN_GRIPPER=100`，`RETURN_HANDLE=150`，
`OPEN_AND_CLEAR=100`，`RETREAT_ARM=200`，`PUSH_ARM_RETRACT=300`，
`BASE_ADVANCE=900` 步；`PUSH_OPEN` 的独立预算为 `900` 步。

全流程使用同一底盘速度契约：机身坐标系 XY 线速度向量模长不超过 `0.4 m/s`，
yaw 角速度绝对值不超过 `0.6 rad/s`。各阶段已有的更严格限制继续生效。

### 当前已确认的阶段接口问题

`PREGRASP -> CENTER_HANDLE` 的接口不满足“下一阶段只沿门板法向直线前伸”的前提。当前
`PREGRASP` 验收的是 EE 到预设悬停点、姿态和稳定性，并不验收真实把手中心是否已经位于
打开夹爪通道的横向及竖直中心。因此 `PREGRASP` 可以在 Z 未居中的情况下通过，
`CENTER_HANDLE` 随后的纯前伸无法消除该误差。PREGRASP 内原有的一次 pocket 左右修正和一次
EE 稳态残差修正已经删除，目标和逆映射路径只在阶段入口生成一次。

### 高刚度逆映射 A/B 结论

两组高刚度实验使用相同 stiffness `10000`、damping `200`、seed 1700--2699、四卡四进程组织、
3000 step 上限和终止快照。恢复真实逆映射后，APPROACH 失败保持完全相同的 `132`，而
PREGRASP 失败从 `342` 降至 `97`，完整成功数从 `84` 提升到 `129`。因此此前 PREGRASP 的
退化明确来自绕过真实逆映射链路，不是随机 seed 差异，也不是提高 stiffness 本身造成。

逆映射恢复后，失败主要转移到 GRASP_HANDLE `340` 和 CENTER_HANDLE `191`。这说明真实逆映射
恢复了无接触的 PREGRASP 可达性，但 stiffness `10000` 下的抓取接触控制仍然存在独立退化；
不能据此把高刚度、真实逆映射版本迁入正式工作区。

CENTER_HANDLE 的 191 个失败按失败码拆分为：超时 141、指尖力超过 `600 N` 的安全终止 48、
夹爪到门板间隙小于 `5 mm` 的几何安全终止 2。超力占 `25.1%`，不是该阶段的主要失败来源；
48 个超力样本的 episode 峰值中位数为 `981.2 N`，最大为 `2380.4 N`。

141 个超时样本中，103 个在终止帧仍违反夹爪通道中心误差 `<=18 mm`，72 个违反水平误差
`<=22 mm`，45 个违反 EE 前伸终点误差 `<=12 mm`，这些条件可以重叠。按验收顺序互斥归因，
91 个首先卡在通道中心误差，45 个首先卡在前伸终点误差，其余 5 个分别卡在把手法向、上侧
间隙或底盘/机械臂稳定性。因此 CENTER_HANDLE 的首要问题是插入后的夹爪与把手几何不对准，
过大接触力是次要但仍显著的问题。

## 目标与约束

目标是在一个 `SimulationApp` 中运行 1000 个以上环境，并逐步把逐环境控制、状态变换、
阶段判定和可批处理数学迁移为 GPU 或混合向量化实现，为后续大规模数据采集提供吞吐。

所有修改遵守以下准入流程：

1. 先用 profile、代码和轨迹确认一个具体热点或行为问题。
2. 候选只在隔离实验仓库实现，不直接覆盖正式工作区。
3. 先做 scalar shadow 或逐步 trace，再做同条件 A/B。
4. 验证目标问题改善，并确认已有成功 seed、左右门和阶段语义无回归。
5. 通过后只迁入最小实现；新机制替代旧机制时删除实验开关和废弃路径。

## 已通过：CONTACT_PANEL 精确 worker 后端

### 根因与拒绝方案

CONTACT_PANEL 的稳态逆映射是带关节边界的 Pinocchio/SciPy 连续优化。GPU 固定 DLS 在
